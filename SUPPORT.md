# Support

## Where to ask

| I need… | Go to |
|---|---|
| Help using a specific project | That repository's **Discussions**, or its issues if discussions are off |
| To report a bug | That repository's **Issues** → *Bug report* |
| To request a feature | That repository's **Issues** → *Feature request* |
| To report an outage or incident | [`.github` issues](https://github.com/Mtl-Logistics/.github/issues) → *Incident* |
| Access to a repo, team or secret | [`.github` issues](https://github.com/Mtl-Logistics/.github/issues) → *Access request* |
| To report a vulnerability | **Not an issue** — see [`SECURITY.md`](SECURITY.md) |

## Before you open an issue

- Search existing issues, open and closed — your problem may already be known.
- Check the repository README and its `docs/` directory.
- Have the details ready: version or commit, environment, exact error output,
  and the minimum steps that reproduce the problem.

## Response expectations

This is a working engineering organization, not a 24/7 support desk. Issues are
triaged on business days. Production incidents raised through the incident
template take priority over everything else.

## Contributing a fix

Found the problem and know the answer? A pull request is very welcome — read
[`CONTRIBUTING.md`](CONTRIBUTING.md) first.
